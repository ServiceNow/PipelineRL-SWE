\begin{abstract}
Routing software repair tasks across a portfolio of models requires estimates
of which model will succeed on each task---but this is hard from the problem
statement alone, because input context rarely reveals which solver will produce
a valid patch.
We study \emph{post-scout routing}: always run a cheap 4B scout model first,
then route based on the combined context of the problem and scout attempt.
The scout output is load-bearing: on a 286-task SWE-Smith evaluation set,
a post-scout router achieves ROC-AUC 0.720 and 75.6\% accuracy at
70\% abstention, compared to ROC-AUC 0.652 and 65.1\% for an input-only ablation
trained on the same 1{,}500 real execution labels---a +10.5 point gain at the
high-abstention regime.
A two-stage proxy pre-training procedure further reduces the real-label
budget: post-scout proxy+real training with as few as 50 real labels
(ROC-AUC 0.698) already exceeds input-only routing with 1{,}500 labels.
Finally, the same predicted reward vectors that drive abstention enable a
flexible cost-aware local routing policy: by tuning a single inference-time
penalty $\lambda$---without retraining---the router traces a Pareto frontier
from 18\% cost reduction ($\lambda{=}0$) to over 85\% cost reduction,
demonstrating that the scout output simultaneously improves task-difficulty
estimation and enables fine-grained routing.
\end{abstract}

\section{Introduction}

Large language models for software repair span a wide range of cost and
reliability.
A 4-billion-parameter model costs a fraction of a 120-billion-parameter model
per token, but the larger model solves a substantially higher fraction of repair
tasks.
An organization running a portfolio of models benefits from a router that
directs each task to the cheapest solver likely to succeed---and escalates to a
powerful external model only when the local portfolio is expected to fail.

Standard routing approaches predict solver quality from the task input alone.
For code repair, this is difficult: two tasks with similar-looking bug reports
may require fundamentally different fix strategies, and one model may succeed
where another fails for reasons not apparent from the problem statement.
Cascade systems \citep{chen2024frugalgpt} alleviate this by calling solvers
sequentially and stopping when a learned confidence threshold is met,
but this requires running each solver before deciding to continue---and a
full cascade that observes all four model outputs before routing is
60$\times$ more expensive than simply observing the scout output.

We propose running a cheap \emph{scout} model as the first step,
then routing based on the scout attempt.
The scout exposes structure that the problem statement cannot:
whether the model can localize the bug, which files and functions are relevant,
whether the fix involves simple substitution or structural change,
and whether the attempt is a format failure.
All of this information is available before invoking any additional solver.

A key practical challenge is label cost.
Execution-based labels require running the full SWE-bench evaluation harness
for every (task, model, attempt) triple.
We address this with two-stage training: first pre-train on dense proxy rewards
(patch-similarity scores, cheap to compute without test execution), then
fine-tune on a small number of real labels.
With this procedure, post-scout routing with only 50 real labels already
outperforms input-only routing with 1{,}500 real labels.

Beyond abstention, the same predicted reward vectors support cost-aware
\emph{local routing} via a single inference-time penalty coefficient $\lambda$.
By increasing $\lambda$, the router trades accuracy for cost reduction without
any retraining, tracing a Pareto frontier that is inaccessible to an
input-only router without per-task cost proxies.

Our contributions are:
\begin{itemize}
\item We demonstrate that the 4B scout attempt is a load-bearing signal:
  post-scout routing achieves ROC-AUC 0.720 and 75.6\% accuracy at 70\%
  abstention versus 0.483 and 65.1\% for input-only routing on the same
  1{,}500 real labels---a gap that grows with abstention rate.
\item We show that proxy pre-training dramatically reduces the real-label
  budget: post-scout proxy+real with $N{=}50$ real labels (ROC-AUC 0.698)
  exceeds input-only routing with 1{,}500 real labels (ROC-AUC 0.652),
  a 30$\times$ label reduction.
\item We establish that the same predicted rewards enable flexible inference-time
  cost-aware routing via $\lambda$ tuning, tracing a Pareto frontier from 18\%
  to over 85\% cost reduction relative to always-120B, without retraining.
\end{itemize}

\section{Problem Formulation}
\label{sec:problem}

\paragraph{Repair tasks and solver portfolio.}
Let $\mathcal{X}$ denote a distribution of software repair tasks,
where $x \in \mathcal{X}$ consists of a natural-language issue description
and relevant repository file contents.
We have a portfolio of $K+1$ local solvers
$\mathcal{M} = \{m_0, m_1, \ldots, m_K\}$,
ordered by increasing cost.
Solver $m_i$ produces a patch $y_i = m_i(x)$,
and the real reward $r_i(x) \in \{0, 1\}$ is 1 if the patch passes
the task's test suite and 0 otherwise.
Beyond the local portfolio we have access to an external frontier model
$m_\mathrm{ext}$ (e.g.\ Claude Sonnet) at substantially higher cost.

\paragraph{Scout and post-scout context.}
We designate $m_0$ as the \emph{scout}: the cheapest model, always run first.
After observing $y_0 = m_0(x)$, the router has access to the
\emph{post-scout context}
\[
    z = (x,\, y_0).
\]
The routing decision is made from $z$, before any further solver is called.
The action space is
\[
    a \in \{0, 1, \ldots, K, \text{ext}\},
\]
where $a = 0$ means accept the scout output, $a \in \{1,\ldots,K\}$ means
invoke the $a$-th local solver, and $a = \text{ext}$ means escalate to the
external model.

\paragraph{Abstention as escalation.}
In the deployment scenario we study, the router makes a \emph{binary}
decision for each task: either invoke the best local solver $m_K$
(the 120B model), or abstain and escalate to the external model $m_\mathrm{ext}$.
There is no within-portfolio routing in the abstention evaluation;
the question is purely whether the local portfolio is worth attempting at all.
We refer to this binary call-or-escalate decision as \emph{abstention}.

Formally, the router assigns each task a scalar confidence score
$s_\theta(z) \in \mathbb{R}$, higher meaning more confidence that the
best local solver will succeed.
Tasks above the threshold are sent to $m_K$; tasks below are escalated
to $m_\mathrm{ext}$.
The primary evaluation metric is the \emph{ROC AUC}:
\[
    \mathrm{ROC\text{-}AUC}
    \;=\; \Pr\!\left[s_\theta(z^+) > s_\theta(z^-)\right],
\]
where $z^+$ is a task on which $m_K$ succeeds and $z^-$ is one on which
it fails, drawn independently.
A random signal scores 0.5; a perfect signal scores 1.0.
We additionally report \emph{accuracy at abstention rate $\alpha$}:
\[
    \mathrm{ACC}(\alpha) \;=\;
    \frac{1}{|\mathcal{R}(\alpha)|} \sum_{x \in \mathcal{R}(\alpha)} r_K(x),
\]
the fraction of retained tasks (top $1{-}\alpha$ by score) on which
$m_K$ succeeds.

\paragraph{Oracle and random baselines.}
The oracle sets $s_\theta(z) = r_K(x)$: it abstains on exactly the tasks
that $m_K$ fails on, achieving ROC-AUC $= 1.0$.
The random baseline scores tasks uniformly at random (ROC-AUC $= 0.5$).
On our 286-task evaluation set, $m_K$ (120B) fails on $52.8\%$ of tasks
and the overall 120B success rate is $47.2\%$.

\paragraph{Cost-aware local routing.}
Beyond abstention, the router's predicted reward vector
$\hat{\mathbf{r}}_\theta(z) \in [0,1]^K$ can be used to select among
local routes.
Define the size-adjusted cost of route $r$ as
\[
    c_r \;=\; \frac{\mathrm{params}_r}{4} \times \mathbb{E}[\text{output\_tokens}_r],
\]
where $\mathrm{params}_r$ is the model size in billions.
The cost-penalised utility of route $r$ is
\[
    \hat{u}_r(z) \;=\; \hat{r}_r(z) \;-\; \lambda \cdot c_r(z),
\]
and the router selects $\arg\max_r \hat{u}_r(z)$.
Varying $\lambda \geq 0$ at inference time---without retraining---trades
task reward for cost reduction, tracing a Pareto frontier.
For the post-scout router, $c_r(z)$ is estimated per-task using the scout
output token count as a proxy for task difficulty.

\section{Architecture}
\label{sec:arch}

\paragraph{Shared encoder.}
All router variants use \texttt{Qwen/Qwen3-Embedding-8B} as the text encoder,
fine-tuned with LoRA adapters on the query, key, value, and output projections
(\texttt{q\_proj}, \texttt{k\_proj}, \texttt{v\_proj}, \texttt{o\_proj}).
We use rank 32, alpha 64, and LoRA dropout 0.05.
The encoder is run with Flash Attention 2 in bf16 with gradient checkpointing.
A two-layer MLP with hidden size 1{,}024 maps the \texttt{[EOS]} token
embedding to the prediction target.

\paragraph{Post-scout router.}
The post-scout router encodes the full post-scout context $z = (x, y_0)$:
the repair prompt (problem statement and file context) followed by the scout
output $y_0$.
Its prediction head outputs a vector $\hat{\mathbf{r}}_\theta(z) \in [0,1]^4$,
one scalar per route, predicting the probability that each solver $m_i$ will
succeed on the task.
The abstention score is the mean predicted reward,
$s_\theta(z) = \frac{1}{4}\sum_{i=0}^{3} \hat{r}_i$.

\paragraph{Input-only router.}
The input-only router is an ablation that encodes only $x$, not $y_0$.
It shares the same architecture, head structure, and training objective
as the post-scout router.
This directly measures the marginal value of the scout attempt.

\paragraph{Cascade verifier.}
The cascade verifier encodes a single route's context $(x, y_i)$---the
problem paired with one solver's output---and predicts whether that solver
succeeded.
It produces a scalar $\hat{p}_\theta(x, y_i) \in [0,1]$.
At inference time, the verifier is applied to $y_0$ (the scout output),
and the resulting score is used as the abstention signal:
$s_\theta(z) = \hat{p}_\theta(x, y_0)$.
This is the fairest comparison to the post-scout router, since both observe
exactly $(x, y_0)$ at decision time and pay the same scout cost.
By contrast, a cascade that observes all four solver outputs before routing
has a strictly later information state and a 60$\times$ higher decision cost
(Section~\ref{sec:cascade_cost}).

\section{Training}
\label{sec:training}

\paragraph{Training objective.}
For all router variants, we optimise binary cross-entropy against per-route
success labels:
\[
    \mathcal{L}_\mathrm{BCE}(\theta)
    = -\frac{1}{N} \sum_{n=1}^{N}
      \sum_{i=0}^{K}
      \left[
        r_i^{(n)} \log \hat{r}_i^{(n)}
        + (1 - r_i^{(n)}) \log (1 - \hat{r}_i^{(n)})
      \right].
\]
We additionally train a route-delta auxiliary term that directly
supervises pairwise reward differences:
\[
    \mathcal{L}_\mathrm{aux}(\theta)
    = \frac{1}{N} \sum_{n=1}^{N}
      \sum_{i < j}
      \left[
        (\hat{r}_i^{(n)} - \hat{r}_j^{(n)}) - (r_i^{(n)} - r_j^{(n)})
      \right]^2.
\]
The full real-label fine-tuning objective is
$\mathcal{L} = \mathcal{L}_\mathrm{BCE} + \lambda_\mathrm{aux}
\mathcal{L}_\mathrm{aux}$
with $\lambda_\mathrm{aux} = 1.0$.

\paragraph{Proxy labels.}
Real execution labels require running the full test suite for each
(task, solver) pair.
As a cheaper alternative, we compute a \emph{proxy reward} by comparing
the predicted patch to the gold patch:
\[
    \tilde{r}_i(x) = \frac{1}{|F|} \sum_{f \in F}
      \operatorname{SequenceMatcher}(\hat{d}_f,\, d_f^*),
\]
where $F$ is the union of files in the predicted and gold diffs,
$\hat{d}_f$ is the predicted file-level unified diff,
$d_f^*$ is the gold file-level unified diff,
and SequenceMatcher returns the normalised longest-common-subsequence ratio.
Format errors receive $\tilde{r}_i = 0$.
The proxy reward lies in $[0,1]$ and is cheap to compute without test execution.

\paragraph{Two-stage training.}
In the first stage (\emph{proxy pre-training}), the model is trained on a
trace-expanded dataset of ${\sim}12{,}000$ tasks with proxy labels:
\[
    \theta_\mathrm{proxy} = \arg\min_\theta\;
    \mathcal{L}_\mathrm{BCE}(\theta;\, \tilde{r}).
\]
In the second stage (\emph{real fine-tuning}), the proxy-pre-trained weights
are fine-tuned on $N$ tasks with real execution labels:
\[
    \theta_\mathrm{final} = \arg\min_\theta\; \mathcal{L}(\theta;\, r),
    \quad \theta \leftarrow \theta_\mathrm{proxy}.
\]
The second stage uses only model weights from the first stage, not optimizer
state, and runs for 10 epochs.

\section{Experimental Setup}
\label{sec:setup}

\paragraph{Dataset.}
We evaluate on a 286-task SWE-Smith evaluation set with real execution labels.
SWE-Smith \citep{li2025swesmith} generates software repair tasks from real
GitHub repositories by introducing synthetic bugs and recording gold patches.
Our evaluation subset covers Python, Go, Java, Rust, TypeScript, and other
languages.
All real execution labels are obtained by running the SWE-bench evaluation
harness on AWS and recording per-instance pass/fail outcomes.

The training set for full-supervision runs contains 1{,}500 tasks with real
labels.
The proxy pre-training dataset is a trace-expanded collection of
${\sim}12{,}000$ tasks with proxy rewards computed from scout traces.
For sample efficiency experiments, we subsample
$N \in \{50, 100, 200, 500, 1000\}$
tasks from the real-label training set with a fixed random seed.

\paragraph{Solver portfolio.}
Our four local solvers are:
\begin{enumerate}
\item \textbf{Scout 4B} (\texttt{Qwen/Qwen3-4B-Instruct-2507}):
  size-adjusted cost 942 units; always run first; output forms $y_0$.
\item \textbf{OSS-20B} (\texttt{openai/gpt-oss-20b}):
  size-adjusted cost 11{,}588 units.
\item \textbf{Qwen-30B} (\texttt{Qwen/Qwen3-Coder-30B-A3B-Instruct}):
  size-adjusted cost 6{,}997 units.
\item \textbf{OSS-120B} (\texttt{openai/gpt-oss-120b}):
  size-adjusted cost 37{,}483 units; strongest local solver; abstention
  target $m_K$.
\end{enumerate}
Size-adjusted cost is computed as $\mathrm{params}/4 \times \text{avg output
tokens}$.
The oracle abstention rate is 52.8\% (120B fails on just over half of tasks);
the 120B base success rate is 47.2\%.
All solvers use the same SEARCH/REPLACE repair scaffold with a structured
thinking block and a \texttt{<solution>} section.

\paragraph{External escalation target.}
We evaluate Claude Sonnet as the external frontier model $m_\mathrm{ext}$.
Claude results establish the performance ceiling for the abstention pipeline.

\paragraph{Router training details.}
All routers use the \texttt{Qwen/Qwen3-Embedding-8B} backbone with LoRA rank
32, alpha 64, on \texttt{q/k/v/o\_proj} and additionally
\texttt{gate/up/down\_proj} for the MLP layers.
Training uses AdamW with weight decay 0.01, warmup ratio 0.06,
batch size 1, and gradient accumulation 8.
Real-label fine-tuning runs for 10 epochs at learning rate $10^{-5}$;
proxy pre-training runs for 5 epochs at learning rate $2\times10^{-5}$.
All runs use 4 A100 GPUs with Accelerate DDP, Flash Attention 2, and bf16.

\paragraph{Evaluation metric.}
Our primary metric is the abstention ROC-AUC (Section~\ref{sec:problem}),
computed over a 200-point uniform grid of $\alpha$ values from 0 to 0.85
as a raw trapezoid integral (not normalised by range).
We also report point-wise accuracy at abstention rates 30\%, 50\%, and 70\%.

reflecting that the scout output surfaces task-structural signals
(format failures, localizability, edit scope) that are invisible from
the prompt alone.

\subsection{The Cascade Comparison: Cost vs.\ Quality}
\label{sec:cascade_cost}

The cascade verifier at route-0 (ROC-AUC 0.688) is the only \emph{fair}
comparison to the post-scout router: both observe the same information
$(x, y_0)$ and pay the same decision cost (running the 4B scout only,
size-adjusted cost 942 units).
The post-scout router's multi-route counterfactual head outperforms
the cascade verifier's single-route prediction head by 0.032 ROC-AUC at this
information state.

The ``full cascade'' baseline that observes all four model outputs before
routing is a fundamentally different decision point.
Running all four solvers costs 57{,}011 size-adjusted units before the
routing decision is made---\textbf{60.5$\times$} the cost of the post-scout
abstention step.
For perspective, the 120B run alone (37{,}483 units) costs 40$\times$ more
than post-scout's entire decision pipeline.
At that decision cost, abstention is largely moot: you have already paid
for the most expensive model.
Even at this 60$\times$ cost premium, a full cascade mean over four routes
achieves ROC-AUC 0.752---only \textbf{+0.032} over post-scout (0.720).
The marginal quality gain from a 60$\times$ cost increase is negligible.

\subsection{Cost-Aware Routing via Inference-Time Lambda}
\label{sec:routing_pareto}

The same predicted reward vectors that drive abstention also enable flexible
cost-aware routing within the local portfolio.
By varying the cost penalty $\lambda$ at inference time---without
retraining---the post-scout router traces a Pareto frontier
(Figure~\ref{fig:routing_pareto}).

At $\lambda{=}0$ (pure reward maximisation), the post-scout router achieves
42.3\% success rate at 82.1\% of the always-120B cost---an 18\% cost
reduction.
At $\lambda{\approx}3{\times}10^{-6}$, the frontier passes through
39.2\% success rate at 34.9\% cost (65\% cheaper than always-120B).
At $\lambda{\approx}10^{-5}$, the router achieves 33.2\% success rate
at 11.5\% cost---over 88\% cost reduction.

The post-scout router dominates the input-only router at the high-quality
end of the frontier.
This advantage arises because the post-scout router uses the scout output
token count as a per-task cost proxy: tasks with longer scout outputs tend
to be harder and more expensive across all routes, enabling sharper
cost-reward trade-offs.
The input-only router must use flat historical averages for cost estimation,
losing the per-task signal.

The oracle (cheapest succeeding route per task) achieves 55.9\% success rate
at 10.3\% of always-120B cost---89\% cheaper while delivering higher
accuracy than always-120B (47.2\%).
The large gap between the oracle and learned routers
indicates substantial room for improvement in calibration and cost estimation.

\section{Discussion}

\paragraph{Why does the scout attempt help?}
The input-only and post-scout routers share architecture, objective,
and training data; the only difference is whether $y_0$ is included.
The large gap at high abstention rates (Table~\ref{tab:main}) shows that
the scout attempt contains information about task solvability not recoverable
from the problem statement alone.
The scout reveals \emph{structural} properties: whether the bug is in a
function the model can locate, whether the edit is local or requires global
refactoring, and whether format failures (common at higher difficulty)
are already occurring.
These signals are only observable after a model has attempted the task,
but they are available at the cost of the cheapest model in the portfolio.

\paragraph{The abstention signal and its limitations.}
The abstention signal (mean predicted reward) is a byproduct of multi-route
success prediction: the router is not directly trained to predict task
solvability, but the mean of four route-level predictions correlates with it.
Training directly on a binary solvability target---does any local solver
succeed?---is a natural next step that may close the gap to the oracle.

\paragraph{Routing utility vs.\ abstention.}
Abstention and local routing are complementary decisions from the same
predicted reward vector.
Abstention handles ``will the local portfolio fail?'';
local routing handles ``which cheap solver to use when the portfolio will
succeed?''
The lambda-tuned Pareto frontier shows both decisions can be made from a
single inference pass over the post-scout context.

\paragraph{Limitations.}
The oracle gap is large: the oracle achieves 55.9\% success at 10\% cost,
while the best learned router achieves only 42.3\% at 82\% cost
($\lambda{=}0$).
Closing this gap requires better calibration of per-task difficulty and
route selection.
Our proxy reward does not capture semantic correctness or test coverage,
which limits its utility as a signal for route ranking (as opposed to
task-level solvability).
The four-model portfolio is a fixed snapshot; adding new models requires
re-collecting labels.

\section{Related Work}

\paragraph{LLM routing and cascades.}
FrugalGPT \citep{chen2024frugalgpt} trains a quality estimator and
selects a sequence of LLM calls to balance accuracy and cost.
RouteLLM \citep{ong2024routellm} and RouterBench \citep{hu2024routerbench}
study routing from prompts and preference data.
Router-R1 \citep{zhang2025routerr1} and RadialRouter
\citep{jin-etal-2025-radialrouter} explore reinforcement-learning-based
routing for math and coding tasks.
RouterEval \citep{huang-etal-2025-routereval} provides a systematic benchmark
for router evaluation.
Post-scout routing is distinguished by conditioning on one fixed cheap
attempt and predicting counterfactual outcomes for all solvers simultaneously,
at a fraction of the cascade's decision cost.

\paragraph{Software engineering agents.}
SWE-Bench \citep{jimenez2024swebench} established repository-level issue
resolution as a benchmark for LLM agents.
SWE-Smith \citep{li2025swesmith} scales the dataset by generating
synthetic bugs from real repositories.
SWE-RL \citep{wei2025swerl} trains agents with RL on dense patch-similarity
rewards; we adopt the same proxy reward formulation for router supervision.
Concurrent work on agentic scaffolding \citep{yang2024sweagent} focuses on
improving single-model solve rates; routing is complementary.

\paragraph{Verification and value estimation.}
Process reward models (PRMs) and outcome reward models (ORMs) are widely used
to score reasoning chains \citep{lightman2023verify}.
Our cascade verifier is an ORM that evaluates a completed patch attempt.
The post-scout router extends this to counterfactual multi-route prediction,
predicting outcomes for solvers that have not yet been called.

\section{Conclusion}

We proposed \methodname for software repair agents:
always run a cheap 4B scout model, observe its attempt, then route to the
best local solver or escalate to an external model.
On a 286-task SWE-Smith evaluation set, the scout output is load-bearing:
the post-scout router achieves ROC-AUC 0.720 and 75.6\% accuracy at 70\%
abstention, compared to ROC-AUC 0.652 and 65.1\% for an input-only ablation
with identical supervision---a +10.5 pp gain at the high-abstention regime.
The fairest cascade comparison (verifier at the same $(x,y_0)$ decision point)
reaches ROC-AUC 0.688; a full 4-model cascade costs 60$\times$ more and gains
only +0.032 ROC-AUC.

Two-stage proxy pre-training dramatically reduces the real-label budget:
post-scout proxy+real with only 50 real labels (ROC-AUC 0.698) exceeds
input-only routing at 30$\times$ the label count (ROC-AUC 0.652).
Finally, the same predicted rewards enable flexible inference-time cost-aware
routing without retraining, from 18\% to over 88\% cost reduction.
The oracle---cheapest succeeding route per task---achieves 55.9\% success
at 10\% of always-120B cost, indicating a large calibration gap and an
exciting direction for future work.
